01

Simple Definition

Exception Handling is a way to prevent your program from crashing when something goes wrong and to decide what should happen instead.

💡 Think of it like

A safety net for your code.

try
Code that might fail
catch
Handles the error
finally
Always runs at the end
throw
Creates your own error
02

Analogy — Riding a Bicycle

Imagine you are riding a bicycle. Normally you ride forward and everything is fine. Suddenly there is a pothole — something unexpected happens.

❌ Without Exception Handling

Bicycle hits the pothole. You fall. Journey stops.

"Oops! Something went wrong. Stop everything!"

✅ With Exception Handling

Bicycle hits the pothole. You notice it. You slow down or go around it. Journey continues.

"Oops! Something went wrong. Let's handle it."

03

Breaking It Down

1. try

The try block contains code that might fail. Think: "I'm going to try this operation."

try {
  console.log(user.name); // user might not exist
}
2. catch

The catch block runs if an error happens inside try. Instead of crashing, JavaScript handles the problem.

try {
  console.log(user.name);
} catch (error) {
  console.log("Something went wrong");
}
Output
Something went wrong
3. error Object

The variable inside catch contains information about the error.

try {
  console.log(user.name);
} catch (error) {
  console.log(error.name);    // ReferenceError
  console.log(error.message); // user is not defined
}
📋

Useful error properties

error.name → type of error (e.g. ReferenceError)
error.message → what went wrong

4. finally

The finally block always runs — whether an error happens or not. Think: "No matter what happens, do this at the end."

try {
  console.log("Trying...");
} catch (error) {
  console.log("Error");
} finally {
  console.log("Finished");
}
No error
Trying...
Finished
With error
Error
Finished
5. throw

Sometimes you want to create your own error. That's what throw does. You are manually telling JavaScript: "This situation should be treated as an error."

let age = 12;

if (age < 18) {
  throw new Error("You must be 18 or older");
}
Output
Error: You must be 18 or older
04

How They Work Together

try {
  let age = 12;

  if (age < 18) {
    throw new Error("Age must be 18+");
  }

  console.log("Access granted");
} catch (error) {
  console.log(error.message);
} finally {
  console.log("Check completed");
}
Output
Age must be 18+
Check completed
  • 1Enter try
  • 2Age is checked
  • 3throw creates an error
  • 4JavaScript jumps to catch
  • 5Error handled
  • 6finally runs
  • 7Program continues
05

Real-World Examples

🔐

Example 1 — Login System

User enters wrong password. Instead of crashing, show a message.

try {
  throw new Error("Invalid password");
} catch (error) {
  console.log(error.message); // Invalid password
}
🌐

Example 2 — API Request

You ask a server for data. Possible problems: internet disconnected, server down, request failed. Exception handling lets you respond gracefully.

try {
  const response = await fetch(url);
} catch (error) {
  console.log("Network error");
}
06

Common Confusions

Confusion 1 — Does try prevent errors?

No. It does not stop errors from happening. It only gives you a way to handle them.

Think: A seatbelt doesn't prevent accidents. It helps when accidents happen.

Confusion 2 — Does every bug need try...catch?

No. Use exception handling only where errors are actually possible — API calls, file operations, database operations, user input validation. Not for simple math like let x = 5 + 10.

Confusion 3 — Does code continue after an error inside try?

No. Once an error occurs, JavaScript immediately leaves the try block. Remaining code inside try is skipped.

try {
  console.log("A");
  throw new Error("Oops");
  console.log("B"); // never runs
} catch (error) {
  console.log("Caught");
}
Output
A
Caught
Confusion 4 — Is catch mandatory?

No. You can use try with just finally for cleanup — but most of the time you'll include catch.

Simple Summary

Keyword What it does Think of it as
try Code that might fail Try something risky
throw Creates your own error Sound the alarm
catch Handles the error Deal with the problem

💡 Where you'll use this most

Exception handling becomes especially important when working with Fetch API, Promises, and async/await — because network requests can fail at any time. That's where you'll use try...catch very frequently.
