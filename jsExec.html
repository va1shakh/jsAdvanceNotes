Execution Context,
Call Stack & Event Loop

Beginner-Friendly, Step-by-Step Explanation

01

Simple Definition

Execution Context

An Execution Context is the environment where JavaScript runs your code and keeps track of everything it needs.

Call Stack

The Call Stack is JavaScript's to-do list that keeps track of which function is currently running.

Event Loop

The Event Loop is a manager that checks when asynchronous tasks are finished and sends them back to JavaScript to run.

Stack Overflow

Stack Overflow happens when too many functions are added to the Call Stack and it runs out of space.

Stack Underflow

Stack Underflow means trying to remove something from an empty stack (rarely seen directly in JavaScript).

Big Picture First

Before learning each concept separately, understand this:

When JavaScript runs code:

console.log("Hello");

JavaScript needs:

A place to execute code → Execution Context
A way to remember what is running → Call Stack
A way to handle async tasks → Event Loop

Think of them as a team:

Execution Context = Workspace
Call Stack = Task Tracker
Event Loop = Traffic Police

Imagine plates stacked on top of each other.

Breaking Down Execution Context

Think of it as a workspace. When JavaScript sees:

let name = "John";

function greet() {
  console.log("Hi");
}

JavaScript creates a workspace containing:

Variables: name → "John"
Functions: greet() → function definition

Types of Execution Context

🌐

1. Global Execution Context

Created automatically when the file starts. Think: Whole Program Workspace

let age = 20; // belongs to Global Execution Context
⚙️

2. Function Execution Context

Created whenever a function runs. Think: Function Workspace

function greet() {
  let message = "Hello";
}

greet(); // new workspace created here

06

How Execution Context and Call Stack Work Together

When a function runs:

function greet() {
  console.log("Hi");
}

greet();

JavaScript:

  • 1 Creates Function Execution Context.
  • 2 Pushes it onto Call Stack → greet() | Global
  • 3 Runs the function.
  • 4 Removes it from stack → Global
07

What Problem Does Event Loop Solve?

⚡ JavaScript is Single Threaded

Meaning: One thing at a time.

console.log("A");

setTimeout(() => {
  console.log("B");
}, 2000);

console.log("C");

What should happen?

❌ Without Event Loop

A → (wait 2 seconds) → B → C
That would freeze everything.

✅ With Event Loop
1 A
2 C
3 B
08

Event Loop Step-by-Step

  • 1 Run console.log("A") → Output: A
  • 2 See setTimeout(...) → JavaScript says: "Browser, you handle the timer." Timer starts outside the Call Stack.
  • 3 Continue running: console.log("C") → Output: C
  • 4 After 2 seconds — Timer finishes. Callback goes to: Callback Queue
  • 5 Event Loop checks: Is Call Stack empty? If yes → Move callback into stack → console.log("B") → Output: B

Work Assigned → Work Finished → Waiting Room → Event Loop Checks → Runs Again

09

What is Stack Overflow?

Imagine stacking books forever. Eventually the stack becomes too tall and crashes. Same thing happens in JavaScript.

function hello() {
  hello(); // calls itself forever
}

hello();
💥 Error

The Call Stack grows infinitely: hello() → hello() → hello() → hello() → ...

Eventually: Maximum call stack size exceeded

Why It Happens — usually because of Infinite Recursion with no stopping condition.

❌ Wrong — No stopping condition
function run() {
  run();
}
✅ Correct — Has stopping condition
function run(n) {
  if (n === 0) return;
  run(n - 1);
}
10

What is Stack Underflow?

📭 Imagine

Stack is empty → Then someone says: "Remove a plate." → There is nothing to remove.

That's Stack Underflow.

🛡️

In JavaScript

In data structures, pop from empty stack = Underflow.

The JavaScript engine prevents this internally. So developers almost never see stack underflow errors directly.
