Hoisting in
JavaScript

Beginner-Friendly, Step-by-Step Explanation

01

🧠 Simple Definition

Hoisting in JavaScript means the computer moves variable and function declarations to the top of their scope before running your code.

You can "use" some things before they appear in your code — because JavaScript secretly prepares (hoists) them to the top first.

👉 Think of hoisting like

"JavaScript reads your code twice — first to collect declarations, then to run it."

02

🧩 Breaking It Down (Step-by-Step)

Hoisting applies mainly to two things:

1️⃣

Function Declarations

These are fully hoisted.

sayHello(); // works fine!

function sayHello() {
  console.log("Hello!");
}
✅

This works because:

JavaScript moves the whole function to the top internally.

2️⃣

Variables (var, let, const)

Each behaves differently when hoisted.

🔹 var

Partially hoisted — declaration moves up but not its value.

🔹 let

Hoisted but placed in the Temporal Dead Zone — not usable until its line.

🔹 const

Same as let — hoisted but locked in the Temporal Dead Zone.

var — partially hoisted:

console.log(a); // undefined
var a = 10;

What actually happens inside JS:

var a;             // hoisted (created first)
console.log(a); // undefined
a = 10;           // value assigned later
✅

Key idea

var is hoisted but NOT its value.

let and const — hoisted but NOT usable yet:

console.log(b); // ❌ ReferenceError
let b = 20;

Why? They are hoisted BUT placed in a "dead zone" until the line where they are defined.

👉 This is called — Temporal Dead Zone (TDZ)

Think of it like: The variable exists, but it's locked until JavaScript officially reaches its line.

03

⚠️ Common Confusions

❌ Misconception 1 — "Everything moves to the top"

Not true. Only declarations move — not assignments (like = 10).

❌ Misconception 2 — "Hoisting means code physically moves"

Nope. Nothing actually moves in the file. It's just how JavaScript processes memory before execution.

❌ Misconception 3 — "let and const are not hoisted"

They are hoisted — but they are not accessible before declaration due to the Temporal Dead Zone (TDZ).

04

🧠 Mental Model (Easy to Remember)

Think of JavaScript like a 2-step worker:

  • 1
    Preparation phase — Collects all variable and function declarations. Sets up memory.
  • 2
    Execution phase — Runs your code line by line.
05

🧾 Simple Summary

Type Hoisted? Usable before declaration? Value before declaration
function ✓ Yes ✓ Yes Full function available
var ✓ Yes ⚠ Sort of undefined
let ✓ Yes ✗ No (TDZ) ReferenceError
const ✓ Yes ✗ No (TDZ) ReferenceError
🧾 In short

Hoisting means JavaScript prepares variables and functions before running code.

Functions are fully usable before they appear.
var is hoisted but gives undefined.
let and const are hoisted but blocked until defined (TDZ).
Only declarations are hoisted, not values.
